How Scope and Deliverables Are Defined

SEO work is not a pre-filled checklist: it begins with the website's actual problems, target market and available evidence. A diagnostic review and changes to a live website are separate responsibilities.

  1. Define the brief. Share the website URL, market, business goal and examples of the issue. Identify what access or data would be required.
  2. Agree the work. Define affected pages or templates, research methods, deliverable format and any dependencies before starting.
  3. Document the output. Deliver relevant findings such as an issue register, keyword-to-URL map, content brief or migration plan as specified in the scope.
  4. Validate separately. If implementation is commissioned, agree who makes changes and how results will be checked. Rankings and timing are not guaranteed.

What a Verifiable SEO Finding Looks Like

Illustrative reporting format only — not a real client case, completed audit or ranking claim. Actual findings require website-specific evidence.

Possible problem

An important URL intended for search includes a noindex directive in its returned HTML.

Evidence to collect

Record the URL, HTTP status, source and rendered HTML, robots directives and available Search Console observations.

Recommended decision

Confirm whether exclusion is intentional. Change only the approved directive or template, with rollback instructions if needed.

Acceptance check

Fetch the updated live URL, verify intended robots directives and internal links, then review indexing after recrawling. Removing noindex does not guarantee inclusion.

Verified Internal QA Record — Not a Client Case

To demonstrate the evidence-to-fix workflow, this catalogue's own responsive test uncovered a real defect. These are recorded layout measurements from GitHub Actions, not customer results or a Google ranking improvement.

  1. Observed issue: At 768px width, the anchored category began at 120px while the fixed header reached 171px, leaving the heading covered.
  2. Recorded evidence: The first browser audit reported Anchor obscured by header at 768px. Inspect the failed test.
  3. Approved correction: Increase the catalogue's tablet-only section scroll margin to 192px without changing the global header or other language pages.
  4. Acceptance result: A fresh 768px test measured the section at 192px and the header at 171px, confirming the heading was no longer obscured. Inspect the passing retest.

This illustrates a reproducible QA report for our own project. It does not establish external client experience, predict search performance or replace a website-specific SEO audit.
